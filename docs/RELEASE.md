# Release and Updater

EES-AMS uses Tauri updater signatures and GitHub Releases. The app checks:

```text
https://github.com/Drakaniia/EES-AMS/releases/latest/download/latest.json
```

## One-Time Signing Setup

Generate an updater signing key:

```bash
bun run tauri signer generate -- -w ~/.tauri/ees-ams.key
```

Keep the private key safe. If it is lost, already-installed apps will not trust future update artifacts signed by a different key unless users install a new build with a rotated public key.

Configure GitHub Actions secrets:

- `TAURI_SIGNING_PRIVATE_KEY`: the private key content generated by Tauri.
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`: the key password, if one was set.

The matching public key belongs in `src-tauri/tauri.conf.json` under `plugins.updater.pubkey`.

## Publishing

1. Update `src-tauri/tauri.conf.json` version.
2. Commit the release changes.
3. Tag the commit with the same app version:

```bash
git tag app-v0.1.0
git push origin app-v0.1.0
```

The `Release Desktop App` workflow builds the Windows installer, signs updater artifacts, uploads `.sig` files, and publishes `latest.json` for in-app update checks.

The stable Windows download URL is:

```text
https://github.com/Drakaniia/EES-AMS/releases/latest/download/EES-AMS_windows-setup.exe
```

## Windows Trust Note

Updater signatures protect the update path. They are separate from Windows Authenticode code signing, which is still needed if the project wants to reduce SmartScreen warnings for first-time installer downloads.
